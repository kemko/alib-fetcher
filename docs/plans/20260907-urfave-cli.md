# Переход CLI-флагов на urfave/cli

## Overview

Заменить стандартный пакет `flag` на `urfave/cli` для существующих флагов.
По ответу пользователя `cli-altsrc` исключён из задачи: TOML продолжает
загружаться через `pelletier/go-toml/v2`. Сохранить текущие режимы запуска,
валидацию аргументов и коды выхода.

## Context

- `cmd/alib-fetcher/main.go`: разбор аргументов, `commandOptions`, `commandError`, выбор режима.
- `cmd/alib-fetcher/main_test.go`: CLI-тесты, `useCommandLine`, интеграционные проверки запуска и обслуживания.
- `go.mod`, `go.sum`: новая зависимость `github.com/urfave/cli/v3`, зафиксированная на
  [v3.11.0](https://github.com/urfave/cli/releases/tag/v3.11.0).
- `README.md`, `AGENTS.md`: описание CLI и используемых библиотек. `CLAUDE.md` отсутствует.
- `internal/config` и `internal/process`: существующие загрузка TOML, обслуживание и горячая перезагрузка сохраняются.
- `urfave/cli` v3.11.0 требует Go 1.22; зависимости его `go.mod` уже присутствуют в проекте.
  [go.mod библиотеки](https://github.com/urfave/cli/blob/v3.11.0/go.mod).

## Development Approach

- **Testing approach**: Regular — реализация, затем регрессионные тесты в рамках каждого задания.
- Использовать существующие файлы и функции; не вводить отдельный CLI-пакет,
  подкоманды или флаги глобальных настроек TOML.
- Каждый вызов парсера создаёт собственный `cli.Command`; аргументы и поток вывода передаются явно.
- **CRITICAL: каждое задание включает новые или обновлённые тесты.**
- **CRITICAL: переходить дальше только после успешного `make test`.**
- Проверки и сборка выполняются через Makefile. Коммитить только после полного `make verify`.

## Implementation Steps

### Task 1: Перевести существующие флаги на urfave/cli

**Files:**

- Modify: `cmd/alib-fetcher/main.go`
- Modify: `cmd/alib-fetcher/main_test.go`
- Modify: `go.mod`
- Modify: `go.sum`

- [ ] Добавить `github.com/urfave/cli/v3` v3.11.0 без обновления несвязанных зависимостей.
- [ ] Заменить `flag.CommandLine` на локальный `cli.Command` с `BoolFlag` для `service`/`once`,
  `StringFlag` для `config`/`chat` и `IntFlag` для `forget-latest`; сохранить `./config.toml` по умолчанию.
- [ ] Использовать `IsSet` для различения отсутствующего `forget-latest` и значения `0`,
  а также отсутствующего и явно пустого `chat`. Нормализацию `chat` оставить в `config.NormalizeChatID`.
  Для `forget-latest` задать десятичное основание через `IntegerConfig.Base`; удалить собственный
  разбор числа и методы `flag.Value`.
  [API целочисленных флагов](https://github.com/urfave/cli/blob/v3.11.0/flag_int.go).
- [ ] Сохранить `validateCommandOptions`: ровно один активный режим, положительный `forget-latest`,
  обязательный `chat` для обслуживания и запрет `chat` с `service`.
  Значения `service=false` и `once=false` не выбирают режим.
- [ ] Сохранить одно- и двухдефисные формы флагов, справку без аргументов и по `-h`/`-help`/`--help`.
  Использовать штатную справку библиотеки; отключить встроенную подкоманду `help`
  и отклонять позиционные аргументы.
- [ ] Объединить ошибки разбора и валидации в путь с выводом ошибки и справки и возвратом `commandError`.
  Оставить завершение процесса и коды `2`/`1` в `main`; справка возвращает успех без чтения TOML.
  Для этого доступны `Writer`, `ErrWriter` и `ExitErrHandler`.
  [API cli.Command](https://github.com/urfave/cli/blob/v3.11.0/command.go).
- [ ] Обновить CLI-тесты и `useCommandLine`, убрав подмену `flag.CommandLine`; проверить успешный
  разбор каждого режима, справку, ошибки и повторные вызовы без накопления состояния.
  Выполнить `make fmt` и `make test`.

### Task 2: Проверить критерии приёмки

**Files:**

- Modify: `cmd/alib-fetcher/main_test.go`

- [ ] Дополнить таблицы тестов: отсутствующий и конфликтующие режимы, неизвестные флаги,
  позиционные аргументы, пропущенные значения, некорректные `bool`, ноль,
  отрицательное число, переполнение и нечисловой `forget-latest`.
- [ ] Проверить отрицательный числовой `chat` через пробел и через знак равенства,
  нормализацию `@channel`, явно пустой и неверный `chat`, а также различие отсутствующего
  флага и явно заданного значения.
- [ ] Проверить справку и ошибки с отсутствующим конфигом: разбор аргументов завершается
  до чтения TOML, открытия БД и HTTP-запросов. Проверять содержание справки,
  не фиксируя её оформление целиком.
- [ ] Добавить subprocess-проверки `main` для кодов выхода: `0` для справки,
  `2` для ошибок аргументов, `1` для ошибки конфигурации; использовать тестовый
  исполняемый файл без отдельной команды сборки.
- [ ] Сохранить существующие интеграционные проверки `once` для всех и выбранного чата,
  `forget-latest` без сервисных настроек и HTTP, а также горячей перезагрузки.
- [ ] Выполнить `make verify` и `make coverage`; требовать отсутствие замечаний линтера
  и покрытие не ниже 80%.
