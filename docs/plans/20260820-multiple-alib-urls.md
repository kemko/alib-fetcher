# Поддержка нескольких ALIB_URL с частичными результатами

## Overview

Добавить поддержку списка Alib-страниц в `ALIB_URL`, разделённых запятыми. Страницы загружаются последовательно с настраиваемым интервалом `ALIB_REQUEST_INTERVAL`, равным `1s` по умолчанию. Успешно разобранные результаты объединяются и дедуплицируются по `BuyURL`, даже если часть страниц недоступна или повреждена. Ошибки отдельных страниц записываются в структурный лог. GET-параметры сохраняются.

Корректная страница поиска без книг считается успешным пустым результатом. Цикл завершается ошибкой только при отмене контекста или если не удалось успешно обработать ни одной настроенной страницы.

## Development Approach

- **Testing approach**: Regular — сначала код, затем тесты.
- Сохранить поддержку одиночного URL.
- Разделять URL запятыми и обрезать пробелы вокруг элементов.
- Literal-запятую внутри URL требовать в percent-encoded виде: `%2C`.
- Сохранять GET-параметры, порядок URL и исходный порядок книг.
- При совпадении `BuyURL` сохранять первое успешно разобранное объявление.
- Загружать URL последовательно; ждать `ALIB_REQUEST_INTERVAL` только между попытками, включая попытки после ошибки. Одиночный URL не задерживать.
- Ожидание должно учитывать отмену контекста. Отмена остаётся терминальной ошибкой цикла.
- Ошибку отдельной страницы логировать событием `alib.page_failed` с индексом, URL и ошибкой, затем продолжать обработку.
- Если успешно обработана хотя бы одна страница, включая корректную пустую, вернуть объединённый результат без общей ошибки.
- Если все страницы завершились ошибкой, вернуть ошибку после попытки загрузить каждую страницу.
- Не менять интерфейсы и семантику `app.Service` и store.
- Complete each task fully before moving to the next.
- **CRITICAL: every task MUST include new/updated tests**
- **CRITICAL: all tests must pass before starting next task**
