# Двухфазная обработка нескольких ALIB_URL

## Overview

Перестроить `alib.Client.Fetch` в две явные фазы: сначала полностью скачать все настроенные страницы, затем разобрать успешно скачанные ответы и объединить книги в одну общую структуру. Один вызов `Fetch` по-прежнему создаёт один digest независимо от количества URL. Для каждого URL отдельно логировать результат скачивания и, если скачивание успешно, результат парсинга.

## Context

- Files involved:
  - `internal/alib/client.go`
  - `internal/alib/client_test.go`
  - `cmd/alib-fetcher/main_test.go`
  - `README.md`
  - `AGENTS.md`
- Related patterns:
  - `app.Service.Run` уже вызывает `Fetcher.Fetch` один раз, после чего один раз записывает общий результат в store и формирует digest.
  - Текущий `alib.Client.Fetch` обрабатывает URL последовательно, но скачивание и парсинг каждой страницы сейчас чередуются.
  - Межстраничная дедупликация уже использует `BuyURL`, сохраняет первое объявление и исходный порядок.
  - Telegram-заголовок добавляется только в первый chunk; интеграционный тест должен закрепить один заголовок на общий цикл с несколькими URL.
  - URL в логах очищаются от query, fragment и userinfo.
- Dependencies:
  - Новые зависимости не нужны.

## Development Approach

- **Testing approach**: Regular — сначала код, затем тесты.
- Сохранить последовательную загрузку и `ALIB_REQUEST_INTERVAL`.
- Не менять интерфейсы `app.Fetcher`, `app.Service`, store и digest.
- Хранить успешно скачанные ответы в памяти до начала парсинга.
- Сохранить частичный успех: вернуть объединённые книги без общей ошибки, если успешно разобрана хотя бы одна страница, включая корректную пустую.
- Сохранить терминальную обработку отмены context.
- Ввести стабильные события:
  - `alib.page_downloaded`;
  - `alib.page_download_failed`;
  - `alib.page_parsed`;
  - `alib.page_parse_failed`.
- Все события содержат `index` и очищенный `url`; успешный парсинг также содержит `books`, ошибки — `error`.
- Для URL с ошибкой скачивания событие парсинга не создаётся.
- Complete each task fully before moving to the next.
- **CRITICAL: every task MUST include new/updated tests**
- **CRITICAL: all tests must pass before starting next task**
