# TOML-конфигурация, несколько получателей и автоматическая перезагрузка

## Overview

Перенести настройки из окружения в TOML. Для каждого чата или канала задавать собственные поиск и
Telegram-токен. Хранить базы в общем state_path, по умолчанию используя ID получателя в имени файла; разрешить
переопределение имени для подключения старой базы. Добавить автоматическое применение изменений конфигурации.
Запускать сервис только через -service, разовую обработку — через -once с необязательным выбором получателя.
Без аргументов или при ошибках аргументов показывать справку.

## Формат конфигурации

Общие настройки находятся на верхнем уровне. state_path теперь обозначает каталог баз; значение по умолчанию —
/var/lib/alib-fetcher. Остальные существующие значения по умолчанию сохраняются.

Пример TOML:

```toml
state_path = "/var/lib/alib-fetcher"
cron_schedule = "0 0 * * *"
timezone = "Europe/Moscow"
run_on_startup = true
http_timeout = "30s"
alib_max_retries = 3
message_limit = 32000
fresh_books = ""

[[chats]]
chat_id = "-1001234567890"
telegram_token = "REPLACE_WITH_TOKEN"
state_file = "state.db"
categories = ["tramka", "detektivy"]

[chats.filters]
seria = ["Литературные памятники", "ЖЗЛ"]
izdat = ["Наука"]

[[chats.queries]]
author = "Стругацкие"
seria = "Библиотека приключений"
cena2 = "3000"
fotoonly = "da"
lday = "14"

[[chats]]
chat_id = "@another_channel"
telegram_token = "REPLACE_WITH_ANOTHER_TOKEN"

[chats.filters]
title = ["Понедельник начинается в субботу"]
```

## Состояние

- Итоговый путь базы: state_path / state_file. Если state_file отсутствует, используется имя `<chat_id>.db`.
- Числовые ID нормализуются в десятичную запись; @username приводится к нижнему регистру. Примеры имён:
  -1001234567890.db и @another_channel.db.
- state_file задаёт только имя файла внутри общего каталога. Абсолютные пути, разделители каталогов, NUL,
  пустые имена, "." и ".." запрещены. Автоматически построенные имена проходят ту же проверку.
- Относительный state_path разрешается относительно каталога TOML-файла. Путь самого конфига фиксируется при
  запуске.
- В примере первый получатель открывает /var/lib/alib-fetcher/state.db, второй —
  /var/lib/alib-fetcher/@another_channel.db.
- Для подключения прежней базы достаточно указать её каталог в state_path и имя в state_file. Копирование,
  переименование и изменение формата базы не требуются.
- Повторные нормализованные chat_id и совпадающие файлы состояния отклоняются, включая существующие файловые
  алиасы.
- Учёт BuyURL, pending, sent и retention независим для каждого получателя. База открыта только во время его
  дайджеста или обслуживания.
- Смена токена сохраняет историю получателя. Изменение state_path или state_file переключает базу после
  завершения текущих работ; автоматического переноса истории нет. Старые файлы не удаляются.

## Режимы запуска

- alib-fetcher -service — сервис для всех получателей: расписание, callback polling и наблюдение за конфигом.
- alib-fetcher -once — один дайджест для каждого получателя.
- alib-fetcher -once -chat=-1001234567890 — один дайджест только выбранного чата.
- alib-fetcher -once -chat=@another_channel — один дайджест только выбранного канала.
- alib-fetcher -forget-latest 10 -chat=-1001234567890 — обслуживание только выбранной базы.
- Во всех режимах доступен -config; по умолчанию используется ./config.toml.

Правила CLI:

- Должен быть выбран ровно один режим: -service, -once или -forget-latest N.
- -chat необязателен для -once, обязателен для -forget-latest и недопустим для -service.
- -chat выбирает запись по нормализованному chat_id. Неизвестный получатель — ошибка до HTTP-запросов и
  открытия баз.
- Без аргументов, а также по -h/-help, выводится справка с кодом завершения 0. Конфиг при этом не читается.
- Неизвестные флаги, позиционные аргументы, отсутствующие значения, несовместимые режимы, отсутствие режима
  при других аргументах и неположительный N дают диагностику, справку и код 2.
- Ошибки конфигурации или выполнения дают диагностику и код 1.
- -once использует один снимок настроек, не запускает расписание, polling и наблюдение. run_on_startup на него
  не влияет.
- При -once -chat адаптеры и дайджест создаются только для выбранного получателя. Общая TOML-конфигурация
  проверяется целиком.
- При -once для всех ошибка одного получателя не отменяет попытки остальных; итоговая ошибка возвращается
  после их завершения. Отмена контекста останавливает все работы.
- Обслуживание проверяет TOML и настройки выбора базы, но не требует Telegram-токенов, поиска и расписания.
  Сетевых запросов нет.
- Старые переменные окружения больше не читаются.

## Семантика поиска

- categories сохраняет текущую схему адресов с tnew=7 и ограничение на ASCII-буквы.
- filters содержит списки строк. Каждое значение создаёт самостоятельный запрос: две серии и одно издательство
  дают три запроса.
- Каждый элемент queries создаёт один запрос со всеми указанными полями. Для каждого поля разрешена ровно одна
  строка.
- Результаты запросов объединяются. Списки не перемножаются; filters не добавляется автоматически к queries.
- Имена полей совпадают с формой Alib. Представление в Go: map[string][]string для filters и
  []map[string]string для queries.
- Значения — строки, включая числа и флажки. Установленный флажок записывается как "da", выключенный
  пропускается.
- Поддерживаются все 21 поле: author — автор; title — название; seria — серия или художник; izdat —
  издательство; gorodiz — город издания; isbnp — ISBN; god1/god2 — годы; cena1/cena2 — цены; sod — аннотация;
  bsonly — продавец; gorod — город продавца; lday — последние дни; noreprint — исключить репринты; nograv —
  исключить гравюры; fotoonly — наличие фото; minus — минус-слова; sumfind — диапазон цен; tipfind — рубрика;
  sortby — сортировка.
- sumfind принимает "1"–"5", sortby — "0"–"10". tipfind использует идентификаторы рубрик формы, включая
  содержащие цифры.
- Bo1 — кнопка отправки; tfind относится к другой форме. В конфигурацию поиска они не входят.
- При отсутствии lday добавляется "7"; явно заданное значение сохраняется.
- Порядок источников: категории, filters в порядке полей формы, queries в порядке TOML. Порядок значений
  массивов сохраняется. Повторные URL удаляются с сохранением первого.
- Значения кодируются в Windows-1251, затем через net/url. Неизвестные поля, неверные типы, пустые значения и
  запросы, недопустимые значения флажков/select и непредставимые символы отклоняются.
- Каждый получатель должен иметь хотя бы один источник поиска.

## Telegram и выполнение

- На каждого получателя создаётся собственный runner с существующей блокировкой startup/scheduled/refresh.
  Разные получатели могут работать независимо.
- Одинаковый токен разрешён нескольким получателям. На уникальный токен работает один SDK-клиент и один
  poller; Sender хранит привязку к конкретному chat_id.
- Callback маршрутизируется по клиенту токена и чату. Чужое или неоднозначное нажатие получает ответ без
  запуска дайджеста.
- Сохраняются подтверждение чанков, retry_after, порядок удаления старой кнопки и отправки новой, немедленный
  ответ на refresh и отмена по контексту.
- TELEGRAM_API_BASE, APIBase и WithServerURL удаляются. Используется стандартный адрес SDK; HTTP-тесты
  подменяют transport.
- Расписание, таймауты, повторы и форматирование общие. Поиск, токен, получатель и имя базы индивидуальны.
- Логи конкретного получателя содержат chat_id. Токены и содержимое TOML в логи не попадают.

## Перезагрузка

- Начальная конфигурация полностью проверяется до запуска работы.
- В -service содержимое файла проверяется раз в секунду. Обычная запись и замена через atomic rename
  обнаруживаются одинаково.
- Сначала полностью разбирается и проверяется кандидат. Ошибка чтения, удаление файла, неверный TOML или
  значения сохраняют рабочую конфигурацию.
- Валидный кандидат приостанавливает новые дайджесты. Начатые завершаются со старым снимком настроек; polling
  продолжает отвечать на нажатия, пропуская новые запуски.
- После завершения всех текущих работ файл проверяется повторно. Применяется актуальная валидная версия; при
  ошибке или отмене изменения работа возобновляется с прежней конфигурацией.
- Настройки заменяются целиком. Старые poller завершаются до запуска новых; для сохранившихся токенов
  переиспользуются SDK-клиенты с их offsets.
- Таймауты SDK изменяются только после завершения старых запросов и polling.
- Существующие получатели не получают повторный startup-дайджест. Новые получают его согласно run_on_startup.
  Удаление получателя сохраняет базу.
- Изменения только комментариев и оформления не перезапускают работу. Повтор одной ошибочной версии не
  засоряет логи.
- SIGINT/SIGTERM отменяет запросы и ожидания, останавливает наблюдение и дожидается завершения всех работ.

## Development Approach

- **Testing approach**: Regular — реализация, затем регрессионные тесты.
- Задачи выполнять последовательно и полностью завершать каждую перед переходом к следующей.
- **CRITICAL: every task MUST include new/updated tests.**
- **CRITICAL: all tests must pass before starting next task.**
- Перед переходом к следующей задаче должны проходить make verify и все тесты текущей задачи. Команды
  выполнять через rtk.

  рабочим Alib и Telegram.

- README обновлять вместе с поведением. Коммитить только завершённые части после успешного make verify.
- Не добавлять совместимость с окружением, общий конфигурационный фреймворк или собственный язык фильтров.

## Ограничения

- Перезагрузка ждёт текущие дайджесты, включая retry_after. Общий deadline не добавляется; сигнал завершения
  отменяет ожидание.
- Изменение обнаруживается примерно за секунду. Сохранение через atomic rename предпочтительно: валидную
  промежуточную запись нельзя надёжно отличить от законченного конфига.
- Смена имени/каталога базы или chat_id без сохранения прежнего state_file может привести к повторной отправке
  объявлений из-за новой истории.
- Retention остаётся 14 дней. Поиск за больший период может повторно обнаруживать объявления после удаления
  истории.
- Пагинация поиска не добавляется.
