# Убрать паузы между запросами, добавить библиотечный backoff и сообщение об отсутствии новых книг

## Overview

Запрашивать страницы Alib последовательно без постоянной паузы. При ошибке загрузки повторять запрос через
cenkalti/backoff с увеличивающейся задержкой; по умолчанию — три дополнительных попытки. Если отправлять нечего,
присылать «Новых книг не обнаружено.» с кнопкой «Обновить».

## Context

- internal/alib/client.go — последовательная загрузка, ожидание между страницами, последующий парсинг.
- internal/config/config.go, cmd/alib-fetcher/main.go, docker-compose.yml — настройка и передача
  ALIB_REQUEST_INTERVAL.
- internal/digest/render.go — сейчас возвращает пустой результат, когда нет книг и ошибок.
- internal/app/service.go — общий путь отправки, BeforeDelivery, подтверждение доставки и Telegram retry_after.
- internal/process/callbacks.go — удаление кнопки на нажатом сообщении через BeforeDelivery.
- Регрессионные тесты находятся рядом с перечисленными файлами.
- Новая зависимость: github.com/cenkalti/backoff/v7, зафиксированная версия v7.0.0. Библиотека предоставляет
  готовые Retry и ExponentialBackOff. [Документация](https://github.com/cenkalti/backoff/tree/v7.0.0).
- Библиотека использует MIT и не имеет внешних зависимостей; требуемый Go 1.23 совместим с проектным Go 1.26.5.
  [Лицензия](https://github.com/cenkalti/backoff/blob/v7.0.0/LICENSE),
  [go.mod](https://github.com/cenkalti/backoff/blob/v7.0.0/go.mod).

## Development Approach

- Regular: сначала код, затем регрессионные тесты.
- Выполнять задачи последовательно; перед переходом дальше весь набор тестов должен проходить.
- Каждую задачу сопровождать новыми или обновлёнными тестами соответствующего поведения.
- Делегировать библиотеке цикл повторов, расчёт задержек, таймеры и прерывание ожидания по context. Использовать
  Retry непосредственно вокруг существующей загрузки страницы.
- Не создавать собственный retry-пакет, универсальные обёртки или тестовую инфраструктуру для таймеров. Проверять
  интеграцию с загрузчиком, не дублировать тесты алгоритма библиотеки.
- Сообщение об отсутствии новых книг отправлять при пустой очереди и отсутствии ошибок книг. Сохранённые
  pending-книги отправлять даже без новых находок; при ошибках книг сохранять существующую сводку.
- Существующую политику Telegram retry_after сохранить.
